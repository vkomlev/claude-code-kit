# Настройка комплекта под свои проекты

Комплект — основа, а не готовая под тебя конфигурация. Ниже — что стоит поправить после
установки, от обязательного к необязательному.

## 1. Общие правила `~/.claude/CLAUDE.md` (обязательно)

Шаблон `CLAUDE.md.example` — универсальный. Пройди по нему и подгони:

- **Стек.** Стандарты кода написаны для Python — если у тебя Node/Go/другое, замени раздел
  «Стандарты кода» на свой (аннотации типов, обработка ошибок, логирование, стиль).
- **Язык.** Если общаешься с агентом не на русском — поправь раздел «Язык общения».
- **Коммиты.** Формат `<тип>: <описание>` и русские сообщения — под себя (язык, типы, эмодзи).
- **Рабочий цикл.** Оставь те этапы, что реально используешь; лишние убери.
- **NorthStar, гейты, обратная связь.** Можно оставить как есть — это универсальные практики.

Проектные правила (специфика конкретного репозитория) держи не здесь, а в отдельном
`CLAUDE.md` в корне проекта — так глобальные правила остаются чистыми.

## 2. Реестр проектов для гейта `~/.claude/hooks/skill_routing.json` (если ставил хуки)

Замени два примера-правила на свои проекты — по правилу на проект. Подробно — в
`hooks/README.md`. Пока не впишешь свои `root`-пути, гейт просто не будет срабатывать
(это безопасно — он fail-open).

Заодно проверь блок `silencing_by_domain`: там перечислены скиллы, снимающие блок в каждом
домене. Если удалишь какой-то скилл из комплекта — убери его и отсюда.

## 3. Убрать ненужные скиллы (по желанию)

Скиллы независимы — удали лишние папки из `~/.claude/skills/`, чтобы не мешали в списке `/`.
Например, если не занимаешься маркетингом — убери `marketing-*`, `seo-specialist`,
`smm-specialist`, `avito-specialist`, `yandex-direct-specialist`, `creative-brief-designer`.

## 4. Плейсхолдеры внутри скиллов

Некоторые скиллы содержат обобщённые пути-заглушки вроде `<путь к проекту>` или
`<имя-вашей-прод-БД>` — это намеренно. Подставляй конкретику по месту, когда скилл спросит
или когда заводишь скилл под конкретный проект. Прод-хосты и доступы к БД **не** зашивай в
скиллы — держи их в переменных окружения или локальном не-коммитимом конфиге.

## 5. MCP-серверы (по желанию)

Скиллы `/db-check` и `/fastapi-api-developer` умеют работать с БД через MCP-сервер
PostgreSQL, а QA-скиллы — через браузерный MCP. Если хочешь этим пользоваться — подключи
соответствующий MCP-сервер в своём Claude Code (это отдельная настройка, вне комплекта).
Без MCP скиллы всё равно работают, просто без прямого доступа к БД/браузеру.

## 6. Создавай свои скиллы

Когда поймёшь механику — заводи собственные скиллы под свои повторяющиеся задачи через
`/claude-booster` (Режим C для контент-скиллов) или встроенный `skill-creator`. Разовая
задача скилла не требует; повторяющийся класс работы — требует.

---

## Обновление комплекта

`git pull` в папке комплекта → повтори копирование нужных частей. Свои
`CLAUDE.md` и `skill_routing.json` не перезаписывай слепо — переноси изменения вручную.
