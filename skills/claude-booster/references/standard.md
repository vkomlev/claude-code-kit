# Стандарт написания skills для Claude Code

## Обязательный фронтматтер

```yaml
---
name: имя-скилла
version: 1.0.0
description: |
  Краткое описание на русском (2–3 строки).
  Что делает skill и когда его использовать.
allowed-tools:
  - Read          # всегда
  - Bash          # если запускает команды
  - Edit          # если редактирует файлы
  - Write         # если создаёт новые файлы
  - AskUserQuestion  # если интерактивный
  - Glob          # если ищет файлы
  - Grep          # если ищет в коде
---
```

Указывать только те инструменты, которые skill реально использует.

## Обязательные секции (строго в этом порядке)

### `## Роль`
Одна строка: кем выступает Claude при выполнении skill.

Пример: `Старший инженер: провожу независимую проверку кода перед слиянием.`

### `## Когда использовать`
3–5 конкретных триггеров — ситуаций, когда skill уместен.
Формат: маркированный список.

### `## Порядок работы`
Нумерованный список шагов. Каждый шаг — одно действие.
Ссылки на `references/` допустимы для сложных чеклистов.

### `## Контракт результата`
Список полей или артефактов, которые skill производит на выходе.
Формат: маркированный список с именами полей.

### `## Правила качества`
Стоп-условия, минимальные требования, явные запреты.

## Опциональные секции

### `## Формат вопроса`
Для интерактивных skills, которые используют `AskUserQuestion`.
Описывает структуру вопроса: контекст → суть → рекомендация → варианты A/B/C.

### `references/`
Папка с подробными чеклистами для сложных skills.
Основной SKILL.md остаётся коротким — детали выносятся в references.

## Язык

- Весь текст на русском, кроме технических терминов (PASS/FAIL, имена полей, команды)
- `description` во фронтматтере — русский
- Заголовки секций — русский
- Примеры кода и команд — на языке технологии (bash, python и т.д.)

## Версионирование

- Начинаем с `1.0.0`
- `patch` (1.0.x): правки текста, поведение не меняется
- `minor` (1.x.0): новые секции или новые возможности
- `major` (x.0.0): изменение Output Contract или Workflow

## Размер

- Простые skills (executor-lite, spec-writer): 30–60 строк
- Средние skills (review-gate, tech-spec-composer): 60–120 строк
- Сложные skills с references (techlead-code-reviewer, ceo-review): 120+ строк

## Чего избегать

- Не дублировать инструкции из других skills
- Не писать длинные вступления — сразу к делу
- Не смешивать русский и английский в заголовках одного файла
- Не перечислять очевидные шаги ("открой файл", "прочитай задачу")
