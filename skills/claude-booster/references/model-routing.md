# Маршрутизация по контекстным уровням и моделям

Ссылка в `~/.claude/CLAUDE.md`: «Выбор уровня — по model-routing.md. По умолчанию: minimal.»

## Контекстные уровни

- **minimal** — рутина: форматирование, мелкие правки, boilerplate, коммиты, read-only проверки
- **standard** — средняя сложность: спецификации, планы, ТЗ, review PR, многофайловые правки без архитектурного риска
- **full** — архитектура, сложная отладка, финальный quality-gate, UX/UI анализ, кросс-модульные изменения с БД/миграциями

## Критерии эскалации minimal → standard → full

Эскалировать на уровень выше, если верно хотя бы одно:
- Задача трогает контракт между модулями/проектами (API, схема БД, публичный интерфейс skill'а)
- Ошибка необратима или дорога в откате (миграция, публикация, force-push)
- Первый фокусный фикс на этом классе ошибки не сработал
- Задача требует held context из 3+ файлов/систем одновременно
- Оператор явно просит архитектурный разбор или ревью перед мержем

Не эскалировать по умолчанию — избыточный контекст на рутине снижает скорость и не улучшает результат (KPI: «% рутинных задач на уровне minimal»).

## Семейство моделей Claude 5 (актуально на 2026-07)

| Модель | Model ID | Роль |
|---|---|---|
| Fable 5 | `claude-fable-5` | нишевые задачи (см. документацию по мере появления) |
| Opus 4.8 | `claude-opus-4-8` | fast mode, сложные задачи с высоким reasoning effort |
| Sonnet 5 | `claude-sonnet-5` | основная рабочая модель сессии по умолчанию |
| Haiku 4.5 | `claude-haiku-4-5-20251001` | дешёвые/массовые операции, простые субагенты |

Fast mode (`/fast`) переключает на Opus с ускоренным выводом — это не понижение до меньшей модели, доступно на Opus 4.8/4.7.

## Факты о Claude Sonnet 5, влияющие на маршрутизацию

Источник: независимый анализ при выходе модели (не официальная документация Anthropic — держать как ориентир, не как точную спецификацию биллинга).

- **Новый токенизатор** — иное разбиение текста на токены по сравнению с предыдущим поколением моделей
- **Оценка удорожания** — по независимому анализу, реальная стоимость обработки англоязычного текста выросла на ~30-40% из-за нового токенизатора (для русскоязычного текста цифра не приводилась источником — не считать применимой без отдельной проверки)
- **Убраны параметры** `temperature`/`top_p`/`top_k` из API (по данным источника)
- **Контекстное окно** — до 1M токенов
- **Adaptive thinking** включено по умолчанию (модель сама решает глубину рассуждения без явного запроса reasoning effort)

## Как это влияет на решения по маршрутизации

- **Cost-aware fan-out субагентов:** при параллельном запуске большого числа субагентов (Workflow, Agent-фан-аут) с англоязычными промптами закладывать возросшую стоимость токенизации в оценку — не только количество агентов, но и язык промпта
- **Простые/массовые субагенты** (grep-поиск, механические правки, дешёвая классификация) → маршрутизировать на Haiku 4.5 через `opts.model` в Agent/Workflow, не на Sonnet 5 по умолчанию
- **Adaptive thinking по умолчанию** снижает необходимость явно управлять reasoning effort для большинства задач — ручная эскалация effort оправдана только для узкого класса (верификация находок, судейство в панелях агентов)
- Цифра «30-40%» — не проверена по официальным прайс-листам Anthropic на момент завершения этого файла; при планировании бюджета (`budget.total` в Workflow) закладывать как ориентировочный риск, не как точный множитель
