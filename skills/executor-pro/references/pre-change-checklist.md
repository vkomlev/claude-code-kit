# Pre-change checklist

Перед первой правкой прочитать **только релевантные** разделы. Пропускать неприменимые.

## 1. Контракт затрагиваемых функций/API

- [ ] Сигнатуры и типы входов/выходов
- [ ] Побочные эффекты (БД, файлы, HTTP, очереди)
- [ ] Публичность: используется ли из других модулей/сервисов
- [ ] Docstring / OpenAPI spec — текущая версия контракта

**Инструменты:** `Grep` по имени функции, `Read` файла реализации, `Grep` по endpoint path.

## 2. Callers и зависимости

- [ ] Кто вызывает затрагиваемую функцию (`Grep` по имени)
- [ ] Есть ли вызовы из тестов, CLI, pipeline, API
- [ ] Есть ли вызовы из других проектов/сервисов вашего рабочего пространства
- [ ] Обратно совместима ли правка или требуется версионирование

**Правило:** если callers > 10 или вызовы из 3+ модулей — эскалация в full-контекст.

## 3. Существующие тесты

- [ ] Найти тесты для затрагиваемой области (`tests/`, `test_*.py`, `conftest.py`)
- [ ] Прочитать fixtures и shared state
- [ ] Оценить уровень абстракции: unit / integration / e2e
- [ ] Определить, где должен жить regression test (тот же уровень, что дефект)

## 4. БД / миграции / схема

Только если правка затрагивает БД:

- [ ] Нужна ли новая миграция Alembic
- [ ] `version_table_schema='<ваша-схема>'` настроен в env.py миграций
- [ ] Проверить, что миграция не затрагивает `public.alembic_version`
- [ ] Rollback-стратегия: обратная миграция или ручной откат
- [ ] Idempotency: повторный прогон миграции не ломает state
- [ ] Cross-schema: затрагивает ли схемы вне вашей рабочей схемы (если да → `NOT_READY`)

**Инструменты:** `/db-check` перед изменениями, MCP `postgresql` (read-only).

## 5. Pipeline / orchestration

Только для оркестрационных задач (ingest → normalize → enrich → publish → sync):

- [ ] На какой фазе происходит правка
- [ ] Blast-radius: если upstream selection → пустой effective set, останавливается ли downstream
- [ ] Smoke/debug/operator-safe режимы ограничивают ли side effects
- [ ] Fabricated identifiers — НЕТ (запрещено)

## 6. Feature flags / конфигурация

- [ ] Нужен ли новый флаг или переменная окружения
- [ ] Default-значение безопасно
- [ ] Документация в `.env.example` обновлена

## 7. Логирование и наблюдаемость

- [ ] Есть ли логи на критичных путях (`logging`, не `print`)
- [ ] Уровни логирования соответствуют важности события
- [ ] Не логируются secrets / PII

## 8. Git-автоматизация (retry/rebase-логика)

- [ ] Любая автоматизация `git rebase`/`git merge` с retry-циклом явно вызывает
      `git rebase --abort`/`git merge --abort` при неудаче конфликтующей операции
      — иначе `.git` остаётся в mid-operation состоянии, блокирующем ВСЕ
      последующие git-команды в репозитории (включая внешние cron-задачи) до
      ручного вмешательства.

## Выход

После прохождения чеклиста сформировать:
- **Impact map** — список файлов, callers, тестов, миграций
- **Rollback note** — как откатить каждую категорию изменений
- **Regression test plan** — где и на каком уровне писать тест
