## Роль
Технический аналитик: собираю диалоги Claude Code за указанный период, выделяю суть (какие задачи решали, какими инструментами, для чего) и формирую структурированный дайджест.

## Когда использовать
- Нужна сводка "что я делал с AI за день / неделю / диапазон"
- Подготовка контента (реалити-шоу, блог-пост про процесс, еженедельный отчёт)
- Ретроспектива по конкретному проекту
- Приём сессии в pipeline (вход для копирайт-скилла или ретроспективы)
- Быстрое "что мы уже обсудили" по теме за период

## Параметры вызова

### Диапазон времени (обязателен)
| Алиас | Значение |
|---|---|
| `today` | Сегодня, 00:00–текущее время |
| `yesterday` | Вчера, 24 часа |
| `last-Nd` | Последние N дней (например, `last-7d`) |
| `this-week` | Текущая неделя (Пн–Вс) |
| `this-month` | Текущий месяц |
| `YYYY-MM-DD` | Конкретная дата |
| `YYYY-MM-DD..YYYY-MM-DD` | Диапазон дат (включительно) |

### Проект (опционально)
| Алиас | Путь |
|---|---|
| `all` (по умолчанию) | Все проекты |
| произвольный slug | Имя папки проекта в `~/.claude/projects/` |

Можно завести свои алиасы под пути к вашим проектам (например, `myapp` → `<путь к вашему проекту>`), но это опционально — по умолчанию хватает slug папки.

### Примеры
- `/session-digest today` — сегодня, все проекты
- `/session-digest yesterday myapp` — вчера только проект `myapp`
- `/session-digest last-7d` — неделя, всё
- `/session-digest 2026-04-15..2026-04-20 myapp` — диапазон, только один проект

## Порядок работы

### Шаг 0: Загрузка контекста
1. Прочитать `references/jsonl-format.md` — формат JSONL и правила парсинга
2. **Пропуск = СТОП.** Без знания формата skill работает неправильно

### Шаг 1: Парсинг аргументов
- Определить диапазон дат (start_date, end_date) из алиаса
- Определить целевой проект (папка в `~/.claude/projects/` или `all`)
- Если аргументы не переданы — спросить через AskUserQuestion

### Шаг 2: Поиск сессионных файлов
```bash
# Найти папку проекта
ls ~/.claude/projects/
# Slug для project path: путь к проекту → имя папки (диск в upper case, `\` и `:` → `-`)
```

1. Собрать список целевых JSONL-файлов через Glob:
   - `all` → `~/.claude/projects/*/*.jsonl`
   - конкретный проект → `~/.claude/projects/{slug}/*.jsonl`
2. Отфильтровать файлы по mtime (дешёвая предфильтрация): если файл не менялся в диапазоне — пропустить
3. Проверить хотя бы одно событие в диапазоне внутри файла (Grep по timestamp-префиксу)

### Шаг 3: Извлечение полезного сигнала

Для каждого файла в диапазоне:

1. **User-сообщения** — задачи пользователя
   - Фильтр: `type:user`, `content` — строка или массив с `type:text`
   - Отсечь `<system-reminder>...</system-reminder>` блоки (regex)
   - Отсечь `<command-message>`, `<command-name>`, `<command-args>` (оставить суть команды)
   - Отсечь сырые tool_result возвраты внутри user-сообщений

2. **Assistant text-ответы** — первые 2-3 предложения каждого текстового блока
   - Фильтр: `type:assistant`, `content[].type:text`
   - Обрезать до ~300 символов на блок (summary только)

3. **Tool calls** — что физически делал
   - Edit/Write: `file_path` → список изменённых файлов
   - Bash: `description` → список команд с описаниями
   - WebSearch/WebFetch: запросы/URL → список исследований
   - Skill tool: какие skills запускались

4. **Метаданные сессии**
   - sessionId (uuid файла)
   - Время первого и последнего события в диапазоне
   - Проект (папка)
   - Количество сообщений пользователя (маркер глубины сессии)

### Шаг 4: Кластеризация по задачам/темам

Сгруппировать сырой материал в тематические задачи:
1. Пройти по user-промптам хронологически
2. Смежные промпты одной темы → один кластер (по смыслу — анализ семантики)
3. Каждый кластер получает:
   - **Название** — короткая суть (3-7 слов)
   - **Описание** — что решали и зачем (1-3 предложения)
   - **Задействованные инструменты/файлы** — из tool calls
   - **Итог** — что получилось (из финальных assistant-ответов кластера)
   - **Проект** — где это было
   - **Сессии** — список sessionId и временной диапазон

Правила кластеризации:
- Не дробить слишком мелко: "исправил опечатку" и "исправил вторую опечатку" — один кластер
- Не объединять разнородное: работа над skill A и отладка БД проекта B — разные кластеры
- Если один кластер охватил несколько сессий за разные дни — это цепочка, пометить `multi-session: true`

### Шаг 5: Формирование дайджеста

Итоговый markdown-файл по структуре:

```markdown
# Дайджест работы с AI: {период}

**Период:** {start_date} — {end_date}
**Проекты:** {список проектов}
**Сессий:** {количество}
**Задач/тем:** {количество кластеров}

## Сводка одной строкой
{1-2 предложения, главные темы периода}

## Задачи

### 1. {Название кластера}
**Проект:** {project}
**Время:** {диапазон} ({количество сессий})
**Суть:** {описание, 1-3 предложения}
**Инструменты:** {список}
**Изменённые файлы:** {ключевые, не более 10}
**Итог:** {что получилось}

### 2. {Название кластера}
...

## Инструменты в работе
- Edit × N
- Write × N
- Bash × N
- WebSearch × N
- Skills: /имя-скилла × N, /другой-скилл × N

## Метрики периода
- User-сообщений: {N}
- Assistant text-блоков: {N}
- Tool calls: {N}
- Уникальных файлов изменено: {N}

---

```yaml
session-digest:
  version: 1.0.0
  period: {start}..{end}
  projects: [...]
  sessions: {N}
  topics:
    - name: ...
      project: ...
      time_range: [...]
      description: ...
      tools: [...]
      files: [...]
      outcome: ...
      multi_session: false
  totals:
    user_messages: ...
    tool_calls: ...
    files_modified: ...
```
```

### Шаг 6: Сохранение

**Путь:** `<путь к вашему проекту>/output/digest/{YYYY-MM-DD}-digest-{scope}.md`

**Примеры:**
- `2026-04-20-digest-today-all.md`
- `2026-04-20-digest-last-7d-myapp.md`
- `2026-04-20-digest-2026-04-15_2026-04-20-myapp.md`

Создать директорию `output/digest/` если нет.

### Шаг 7: Вывод пользователю

Выдать **сам markdown** (для чтения) — весь файл включая YAML-блок в конце.

Короткое сопроводительное сообщение допустимо: "Дайджест за {период}: {N} задач, {список топ-3 тем}". Больше ничего — файл говорит сам за себя.

## Контракт результата

- `Дайджест` — markdown-файл в `output/digest/` с YAML-блоком в конце
- `YAML-блок` — структурированный срез для машинной подачи в другие skills
- `Сводка в чате` — короткая строка с количеством задач и топ-3 темами
- `Сохранённый путь` — абсолютный путь к файлу

## Интеграция с другими skills

## Правила качества

- **Приватность:** никогда не выдавать сырые секреты/токены/ключи API, даже если они были в сессии. Маскировать через `[REDACTED]`
- **Объём:** один дайджест — максимум 50 кластеров. Если период шире — сначала предупредить и предложить разбить
- **Исключение side-chain:** по умолчанию `isSidechain:false`. Если включать субагентов — спросить
- **Честность:** если JSONL содержит обрезанный текст или повреждённую строку — пометить в дайджесте, не додумывать
- **Без галлюцинаций:** все факты только из JSONL. Нет сессии в диапазоне → сказать явно "нет данных за этот период"
- **Производительность:** для периода > 7 дней — предупредить про время обработки и объём
- **Кодировка:** все файлы читать как UTF-8, писать как UTF-8 (важно для кириллицы)

## Stop-условия

Прерваться и сообщить пользователю:
- В папке `~/.claude/projects/` нет файлов → "Claude Code ещё не запускался в этом окружении"
- В диапазоне нет событий → "За период {start}..{end} нет активности"
- Указан неизвестный проект → показать список доступных slug-ов
- Общий объём JSONL > 500 МБ → спросить подтверждение, предложить сузить диапазон/проект
