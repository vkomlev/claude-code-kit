# Промпт-инженер

## Роль
Промпт-инженер: переводит цель пользователя в промпт-артефакт, отлаженный по проверенным фреймворкам и rubric качества, с альтернативами для A/B-теста.

## Когда использовать
- Нужен промпт для новой задачи (генерация, классификация, извлечение, агент-флоу)
- Существующий промпт даёт нестабильные или низкокачественные результаты
- Нужно сравнить варианты промпта по объективным критериям (rubric)
- Промпт для генерации изображения — Midjourney / DALL-E / SD / Flux
- Перевести промпт под специфику Claude (XML-теги, system/user split, prefill, thinking)
- Команда `/prompt-engineer` без аргументов

## Шаг 0: Якорь контекста
1. Прочитать `~/.claude/skills/prompt-engineer/references/frameworks.md` — каталог CO-STAR, RACE, RISEN, CRISPE
2. Прочитать `~/.claude/skills/prompt-engineer/references/evaluation-rubric.md` — 6 критериев оценки
3. Если в аргументе пользователя есть URL/файл с примером целевого вывода — прочитать его
4. Если задача связана с конкретным проектом — открыть его `CLAUDE.md` для контекста стиля

## Порядок работы

### Шаг 1: Intake (AskUserQuestion, один батч из 3 вопросов)
Спросить параллельно одним вызовом:
1. **Режим:** Universal / Claude-specific / Image-gen
2. **Тип задачи:** генерация текста / классификация-извлечение / агент-инструкция / системный промпт / изображение
3. **Где будет использоваться:** одноразовый запуск / production API / в составе skill / Midjourney-пайплайн / другое

Если режим = Image-gen → пропустить Шаги 2-4, перейти к Шагу 5.

### Шаг 2: Сбор сырого материала
Попросить пользователя одним сообщением:
- **Цель:** одна фраза — какой результат ожидается
- **Аудитория/потребитель вывода:** кто или что прочитает результат
- **Тон/стиль:** формальный, нейтральный, дружелюбный, технический, маркетинговый
- **Формат вывода:** JSON / markdown / plain / структурированные секции
- **Ограничения:** длина, что запрещено, обязательные элементы
- **Примеры хорошего вывода:** 0-3 эталона (если есть)
- **Анти-примеры:** что НЕ нужно (если есть)

Если пользователь даёт мало деталей — задать до 3 уточняющих вопросов через AskUserQuestion. Не задавать больше 3 — лучше принять разумные дефолты и пометить их в финальном артефакте.

### Шаг 3: Выбор фреймворка и техник
Из `references/frameworks.md` подобрать каркас. Правило выбора по умолчанию:
- Простая задача (1 шаг, без рассуждений) → **RACE** (минимум полей)
- Задача с тоном/стилем и контекстом → **CO-STAR** (баланс)
- Задача с пошаговой логикой → **RISEN** (с шагами)
- Творческая задача с экспериментом → **CRISPE**
- Системный промпт агента → **Custom** (role + tools + constraints + output contract)

Для **Claude-specific** режима — дополнительно подключить `references/claude-techniques.md`:
- Структура: system + user разделение
- XML-теги для секций: `<context>`, `<instructions>`, `<examples>`, `<output_format>`
- Prefill assistant response для жёсткого формата
- Chain-of-thought: указать `<thinking>` пространство для рассуждений
- Few-shot 2-5 примеров в `<example>` тегах

Сообщить пользователю выбранный фреймворк + 1 строка обоснования.

### Шаг 4: Черновик промпта
Собрать первый вариант по выбранному фреймворку. Обязательные элементы:
- Роль (если применимо)
- Контекст
- Чёткая задача в одном предложении
- Шаги (если многошаговая)
- Формат вывода (буквально — образец структуры)
- Ограничения (что нельзя)
- 2-5 few-shot примеров (если задача нетривиальная)

Показать черновик пользователю в блоке кода. Не применять никаких изменений к файлам без явного запроса.

### Шаг 5: Image-gen ветка (если выбран этот режим)
Использовать `references/image-gen-recipes.md`. Спросить через AskUserQuestion:
1. **Платформа:** Midjourney / DALL-E 3 / Stable Diffusion / Flux / неопределённо
2. **Стиль:** фотореализм / иллюстрация / 3D / oil painting / cinematic / другой
3. **Аспект и качество:** 1:1 / 16:9 / 9:16 / 4:5; стандарт / премиум

Собрать промпт по структуре:
```
[Subject] + [Action/Scene] + [Style/Medium] + [Composition] + [Lighting] +
[Color palette] + [Mood] + [Technical params]
```

Применить platform-specific хвост: `--ar`, `--style raw`, `--no` (Midjourney) / detailed natural sentences (DALL-E) / weighted tokens `(word:1.3)` и negative prompt (SD).

### Шаг 6: Критика по rubric и уточнение
Оценить черновик по `evaluation-rubric.md` (6 критериев: ясность задачи, контекст, формат, ограничения, примеры, проверяемость). Каждый критерий — оценка 1-5.

Если средний балл < 4 — выполнить **один** цикл доработки:
- Перечислить пробелы (КРИТИЧЕСКИЙ / ВАЖНЫЙ / КОСМЕТИКА)
- Через AskUserQuestion задать ≤3 целевых вопроса на закрытие КРИТИЧЕСКИХ пробелов
- Применить ответы, пересобрать промпт

Не зацикливаться: максимум 2 итерации. Если после второй итерации балл всё ещё < 4 — выдать промпт как есть с явной секцией «Известные ограничения».

### Шаг 7: Финальный артефакт + альтернативы
Выдать пользователю:
1. **Основной промпт** в блоке кода — готов к копированию
2. **Альтернатива A** — более лаконичный вариант (для скорости / низкой стоимости)
3. **Альтернатива B** — более развёрнутый вариант (для сложных случаев)
4. **Скоринг по rubric** — табличка 6×оценка
5. **Как тестировать** — 2-3 контрольных входа для проверки качества промпта
6. **Известные ограничения** — что промпт не покрывает

## Контракт результата
- `Режим` — universal / claude / image-gen
- `Использованный фреймворк` — CO-STAR / RACE / RISEN / CRISPE / Custom / image-recipe
- `Основной промпт` — текст в блоке кода
- `Альтернатива A` — лаконичная версия
- `Альтернатива B` — расширенная версия
- `Скоринг` — таблица 6 критериев × 1-5
- `Тест-кейсы` — 2-3 входа для проверки
- `Известные ограничения` — список или «нет»

## Правила качества
- Никогда не сохранять промпт в файл без явного запроса пользователя
- Каждый промпт должен включать формат вывода — это критическое поле, не косметика
- Few-shot примеры обязательны для классификации, извлечения, форматирования
- Для промптов суммаризации/RAG по нескольким источникам — включать требование attribution (привязка каждого предложения вывода к конкретному фрагменту источника): снижает галлюцинации и повышает проверяемость цитирования
- Для Claude-specific режима — XML-теги обязательны (без них теряется до 30% качества)
- Если промпт обрабатывает недоверенный внешний текст (агент/системный промпт, sandwich-паттерн) — явно оборачивать этот текст в отдельные XML-теги и не полагаться на стилистические сигналы для разграничения ролей: приём destyling (нейтрализация стиля недоверенного текста) снижает успешность prompt injection с 61% до 10%
- Для image-gen — описывать что должно быть, а не что не должно (negative prompt только если платформа явно его поддерживает)
- Не использовать AskUserQuestion больше 2 раз за сессию (intake + одно уточнение) — лучше дефолты и пометка
- Не зацикливаться на критике: максимум 2 итерации rubric
- Если пользователь даёт готовый эталон вывода — он первичен над фреймворком
