# Каталог промпт-фреймворков

Источник истины для Шага 3 SKILL.md. Каждый фреймворк — компоненты, когда применять, мини-пример.

## CO-STAR (универсальный default)
**Компоненты:** Context · Objective · Style · Tone · Audience · Response format
**Когда:** маркетинговый текст, отчёты, любые задачи с тоном и стилем
**Сила:** баланс между структурой и компактностью; явное разделение стиля и тона

Пример каркаса:
```
# Context
[2-4 строки фактуры: ситуация, продукт, рынок]

# Objective
[одна фраза: что должен сделать ассистент]

# Style
[жанр и эстетика: «обзорная статья», «техническая нота», «лендинг-хед»]

# Tone
[эмоциональный регистр: «уверенный», «нейтральный экспертный», «дружелюбный»]

# Audience
[кто читатель: уровень знаний, болевые точки]

# Response format
[структура: разделы, длина, ограничения]
```

## RACE (минималистичный)
**Компоненты:** Role · Action · Context · Expectations
**Когда:** одношаговая задача, нужен промпт за 30 секунд, простой формат вывода
**Сила:** поле Expectations принуждает определить, что значит «хорошо»

Пример:
```
Роль: senior Python разработчик
Действие: написать функцию для парсинга CSV с дедупликацией строк
Контекст: входной файл до 1GB, ключ дедупа — колонки [email, phone]
Ожидаемый результат: код + 3 теста pytest, без внешних зависимостей кроме stdlib
```

## RISEN (с явными шагами)
**Компоненты:** Role · Instructions · Steps · End goal · Narrowing
**Когда:** многошаговая логика, аналитика, исследование, где важна последовательность
**Сила:** Steps заставляет модель показать промежуточные фазы — снижает галлюцинации

Пример:
```
Роль: системный аналитик
Инструкции: проанализируй техническую спецификацию и составь список рисков
Шаги:
  1. Извлечь все функциональные требования
  2. Сопоставить с нефункциональными (нагрузка, безопасность, отказоустойчивость)
  3. Найти противоречия и пробелы
  4. Оценить вероятность × ущерб (low/med/high) по каждому риску
Конечная цель: ранжированный реестр рисков с предложением митигации
Сужения: только риски, влияющие на MVP; игнорировать долгосрочные архитектурные
```

## CRISPE (с экспериментом)
**Компоненты:** Capacity & Role · Insight · Statement · Personality · Experiment
**Когда:** творческая или стратегическая задача, нужно несколько вариантов с разными гипотезами
**Сила:** Experiment даёт 2+ версии с явными допущениями — больше материала для выбора

Пример:
```
Capacity & Role: продуктовый стратег с опытом B2C SaaS
Insight: пользователи бросают онбординг на шаге импорта данных, конверсия 38%
Statement: предложи план улучшения онбординга для роста до 60%
Personality: прагматичный, экономный, оперирует данными
Experiment:
  Вариант А — упростить шаг импорта (предположение: проблема в когнитивной нагрузке)
  Вариант B — переместить импорт после первого «aha»-момента (предположение: ранний барьер ценности)
```

## Custom (агентный системный промпт)
**Когда:** Claude в роли агента с инструментами, длинные сессии, многоходовые задачи
**Структура:**
```xml
<role>
  [Кем выступает агент в одной фразе]
</role>

<context>
  [Постоянная фактура: проект, стек, ограничения]
</context>

<tools>
  [Какие инструменты доступны и когда их использовать]
</tools>

<workflow>
  [Пошаговый протокол работы]
</workflow>

<constraints>
  [Жёсткие запреты: что никогда не делать]
</constraints>

<output_contract>
  [Что агент возвращает на выходе]
</output_contract>

<error_handling>
  [Что делать при ошибках / нехватке контекста]
</error_handling>
```

## Матрица выбора

| Признак задачи                          | Рекомендуемый фреймворк |
|-----------------------------------------|--------------------------|
| Простая, 1 шаг, нет тона                | RACE                     |
| Маркетинг, тон важен                    | CO-STAR                  |
| Многошаговая логика                     | RISEN                    |
| Нужны варианты с гипотезами             | CRISPE                   |
| Агент с инструментами                   | Custom                   |
| Генерация изображения                   | image-gen-recipes.md     |
| Claude API system+user split            | Custom + claude-techniques.md |

## Анти-паттерны
- Вежливые вступления («Будь добр…», «Пожалуйста, помоги…») — занимают токены, не влияют на качество
- «Не делай X» без указания, что делать вместо — модель плохо обрабатывает чистые запреты
- Смешение ролей в одном промпте («ты редактор и копирайтер») — выбрать одну ведущую
- Просьба «думать креативно» без конкретных рамок — рождает шаблонный AI-slop
- Длинный контекст без структуры — выносить в `<context>` теги или markdown-разделы
