# Rubric оценки промпта (6 критериев × 1-5)

Используется в Шаге 6 SKILL.md. Каждый критерий оценивается независимо. Средний балл < 4.0 → требуется итерация.

## Критерии

### 1. Ясность задачи (Clarity)
- **5** — одна фраза однозначно описывает результат; задача проходит «тест ребёнка» (объяснимо без контекста)
- **4** — задача понятна, есть 1-2 второстепенные неоднозначности
- **3** — главное понятно, но есть пробелы в подзадачах
- **2** — задача угадывается, но требует существенной интерпретации
- **1** — задача размыта, модель будет угадывать

### 2. Контекст (Context)
- **5** — достаточно фактуры для качественного ответа без догадок
- **4** — основной контекст есть, мелкие детали могут потребовать домыслов
- **3** — контекст частичный, модель будет заполнять пробелы
- **2** — контекста мало, велик риск галлюцинаций
- **1** — контекст отсутствует или нерелевантен

### 3. Формат вывода (Output format)
- **5** — формат показан буквальным шаблоном с типами полей
- **4** — формат описан, но без полного шаблона
- **3** — формат указан общими словами («верни JSON»)
- **2** — формат подразумевается из задачи
- **1** — формат не задан вообще

### 4. Ограничения (Constraints)
- **5** — явно сказано что можно и что нельзя, длина, источники, запреты
- **4** — основные ограничения есть, мелкие пропущены
- **3** — есть только длина или только запреты
- **2** — ограничения упомянуты вскользь
- **1** — ограничений нет, модель «свободна»

### 5. Примеры (Examples)
- **5** — 2-5 few-shot примеров покрывают типичный, граничный, отказной кейсы
- **4** — есть 1-2 примера, покрытие неполное
- **3** — есть 1 пример или эталон вывода
- **2** — примеров нет, но задача простая и они не критичны
- **1** — примеров нет, а задача сложная и без них не решается

### 6. Проверяемость (Testability)
- **5** — есть 2+ контрольных входа с ожидаемыми выходами; можно объективно оценить
- **4** — критерии успеха ясны, но без конкретных тест-кейсов
- **3** — успех определяется субъективно («хороший текст»)
- **2** — успех вообще не определён, но интуитивно понятен
- **1** — нельзя сказать, удался промпт или нет

## Когда применять освобождение от критерия

- **Примеры (5):** ниже 4 допустимо, если задача — генеративная одноразовая (эссе, креатив)
- **Ограничения (4):** ниже 4 допустимо, если результат не идёт в production
- **Проверяемость (6):** ниже 4 допустимо для разовых исследовательских промптов

В остальных случаях балл < 4 — обязательная итерация.

## Анти-паттерны при оценке
- Не завышать балл из вежливости — это сделает skill бесполезным
- Не занижать ниже реального уровня — две итерации без явной выгоды раздражают пользователя
- Если все критерии 4+, но «что-то не так» — спросить пользователя прямо, что смущает, не выдумывать пробелы
