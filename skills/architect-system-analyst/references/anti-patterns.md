# Архитектурные анти-паттерны

Проверять AS-IS и предлагаемый TO-BE на наличие этих паттернов. Найденный анти-паттерн → запись в `Anti-patterns found` со статусом:
- `ACTIVE` — уже в системе, требует миграции
- `RISK` — TO-BE вводит его, нужно пересмотреть решение
- `ACCEPTED` — осознанный trade-off, зафиксирован в ADR

## Структурные

### Distributed Monolith
Микросервисы, которые должны быть задеплоены вместе. Признаки: общие транзакции между сервисами,
shared schemas, одновременные релизы обязательны.
**Сигнал:** задеплоить один сервис без другого ломает систему.

### Shared Database (как write-target)
Несколько сервисов пишут в одни и те же таблицы.
**Сигнал:** миграция схемы требует координации разных команд / репозиториев.
**Решение:** один writer на таблицу, остальные через API или события.

### God Service / God Module
Один компонент отвечает за 60%+ функциональности или трафика.
**Сигнал:** любой баг или деплой затрагивает весь продукт.
**Решение:** разделить по bounded contexts.

### Synchronous Call Chain (5+ hops)
A → B → C → D → E, где падение любого ломает запрос.
**Сигнал:** latency — сумма latency всех звеньев, нет circuit breakers.
**Решение:** асинхронные события или композиция с защитой.

### Circular Dependencies между модулями
Module A → Module B → Module A.
**Сигнал:** невозможно тестировать модуль изолированно; миграции друг через друга.
**Решение:** вынести общий контракт в третий модуль или изменить направление зависимости.

## Данные

### Dual Write без координации
Пишем и в БД, и в кэш / очередь / внешнюю систему без транзакции или outbox-pattern.
**Сигнал:** inconsistency между source-of-truth и producers.
**Решение:** outbox-pattern или eventual consistency с reconciliation.

### Fabricated Persistence Identifiers
Фиктивные ID (batch_id=0, sentinel FK, placeholder UUID) в production-путях.
**Сигнал:** тесты проходят с mock, а в prod — FK violation или silent data corruption.
**Правило:** запрещено явно (особенно в pipeline-проектах с записью в БД).

### Shared Mutable Global State
Модули читают-пишут общий словарь / файл / глобальную переменную без синхронизации.
**Сигнал:** flaky тесты, race conditions, «работает у меня».
**Решение:** явные контракты, DI, неизменяемые структуры.

### Implicit Contract via DB Columns
Один модуль кладёт JSON в колонку, другой его парсит, без явного контракта.
**Сигнал:** изменение формата ломает consumer без тестового сигнала.
**Решение:** pydantic-модель или JSON schema с валидацией.

## Операционные

### No Rollback Strategy
Миграция или деплой без плана отката.
**Сигнал:** «накатили и молимся».
**Правило:** каждая фаза имеет rollback-note.

### Missing Alembic Schema Isolation
Версионная таблица в `public.alembic_version` вместо target-схемы.
**Сигнал:** коллизии миграций между проектами.
**Правило:** для мульти-схемных проектов задавать `version_table_schema='<ваша_схема>'` обязательно.

### Ambient Test Dependencies
Тест опирается на тестовые данные, которые создал другой тест / среда.
**Сигнал:** тесты падают в CI, проходят локально. Тест нельзя запустить в одиночку.
**Решение:** уникальные ключи на тест, cleanup собственного state.

### Test Coverage в Тестах, но не в Entrypoints
Валидатор работает в unit-тесте, но не вызывается в реальном коде.
**Правило:** validator logic в реальных entrypoints, не только в тестах.

## Организационные

### Documentation Drift
README / ARCHITECTURE / CLAUDE.md отстают от кода.
**Сигнал:** новый человек теряется, Claude выдаёт устаревшие рекомендации.
**Решение:** `document-release` skill после каждого релиза.

### Decision Amnesia
«Почему мы так сделали?» — никто не помнит.
**Решение:** ADR-лог.

### Scope Creep в Bug Fix
Баг-фикс приносит рефакторинг, новые абстракции, «заодно».
**Правило:** баг-фикс = минимальное изменение + regression test на том же уровне абстракции.
