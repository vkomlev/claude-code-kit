# ADR — Architecture Decision Record

Хранить в `docs/adr/NNNN-kebab-title.md`, append-only. Принятые ADR не редактируются — при изменении решения пишется новая запись со статусом `Superseded by ADR-NNNN`.

## Шаблон Michael Nygard (по умолчанию)

```markdown
# ADR-NNNN: <Короткое название решения>

- **Status:** Proposed | Accepted | Deprecated | Superseded by ADR-MMMM
- **Date:** YYYY-MM-DD
- **Authors:** <имя или роль>

## Context

Что за проблема, какие силы на неё давят. Явно: бизнес-ограничения, технические ограничения,
существующие инварианты. Не решение — только картина мира.

## Decision

Что решили. Одно предложение — главное, остальное — пояснения.
Если есть альтернативы, кратко: что рассмотрели и почему отвергли.

## Consequences

### Положительные
- ...

### Отрицательные / риски
- ...

### Нейтральные
- новые контракты, новые зависимости, миграции
```

## Шаблон Y-Statement (для компактных решений)

```markdown
# ADR-NNNN: <Название>

- **Status:** Accepted
- **Date:** YYYY-MM-DD

В контексте <use case / ситуации>,
столкнувшись с <проблемой / противоречием>,
мы решили <выбранный вариант>
**а не** <отвергнутый вариант>,
чтобы достичь <желаемого качества>,
принимая <компромисс / downside>,
потому что <обоснование>.
```

## Правила ADR

- **Одно решение = один ADR.** Не смешивать несвязанные вещи
- **Writing style:** прошедшее время в Decision («Выбрали Postgres»), а не «Будем использовать»
- **Альтернативы обязательны** — если их нет, скорее всего решение не продумано
- **Consequences обязательны** — и положительные, и отрицательные
- **Status lifecycle:** Proposed → Accepted → (опц.) Deprecated / Superseded
- **Нумерация:** сквозная, с нулями (ADR-0001, ADR-0002, ...)
- **Index:** `docs/adr/README.md` со списком всех ADR
- **Хранить рядом с кодом** — в репозитории, не в Confluence / Notion

## Когда писать ADR

- Выбор технологии / БД / протокола
- Смена границ модуля или ответственности
- Отказ от стандартного подхода (например, дубликация вместо централизации — с обоснованием)
- Любое решение, которое через 6 месяцев захочется спросить «а зачем мы так сделали»

## Когда НЕ писать ADR

- Тривиальные правки (переименование, рефакторинг внутри модуля)
- Решения, которые легко обратить (выбор имени переменной, формат логов)
- Кодовые соглашения — они идут в CLAUDE.md / CONTRIBUTING.md
