# Чеклист архитектурного ревью по 6 измерениям

Для каждого пункта выставить статус: `OK` / `WATCH` / `RISK` + 1-2 строки аргументации.
Не заполнять формально — если данных нет, писать `UNKNOWN` и добавлять в `Gaps`.

## 1. Scalability

- [ ] Узкие места по CPU / IO / DB определены
- [ ] Есть понимание текущей нагрузки (RPS, объём данных) и порога роста
- [ ] Горячие пути идентифицированы, индексы/кэши соответствуют паттернам доступа
- [ ] Нет синхронных цепочек 5+ вызовов (anti-pattern)
- [ ] Stateful-компоненты понятны: БД, очереди, файлы — явно разделены

## 2. Security

- [ ] Secrets только в env, не в коде, логах, VCS
- [ ] Валидация входов на границах доверия (user, external API, LLM output)
- [ ] SQL-инъекции / prompt-инъекции — защищены
- [ ] Аутентификация и авторизация: кто что может, где enforced
- [ ] Аудит-логи для чувствительных операций (writes в критичные таблицы, migrations)
- [ ] Зависимости: есть ли lock-файлы, известные CVE

## 3. Maintainability

- [ ] Модульные границы соответствуют домену (bounded contexts)
- [ ] Нет циклических зависимостей между модулями
- [ ] Дубликации пишущих путей к БД → `must-centralize` или явно обоснованы
- [ ] Контракты модулей выражены явно (типы, схемы, события)
- [ ] Сложность функций / цикломатика разумна (<5 ветвей — эталон)
- [ ] Именование и структура предсказуемы (сможет ли новый человек найти код за минуты)

## 4. Performance

- [ ] Latency budget для ключевых операций понятен
- [ ] БД-запросы покрыты индексами, нет N+1
- [ ] Кэширование: что кэшируем, TTL, инвалидация
- [ ] Пакетная обработка против построчной — выбор обоснован
- [ ] Длинные операции асинхронные (background jobs / tasks)

## 5. Deployment / Operability

- [ ] Миграции обратимы, есть rollback-стратегия
- [ ] Alembic isolation (`version_table_schema`) для мульти-схемных проектов
- [ ] Конфигурация через env / config-файлы, без хардкода
- [ ] Локальная разработка воспроизводима (README setup работает с нуля)
- [ ] CI / pre-commit hooks настроены и используются
- [ ] Blast-radius изменений понятен: что ломается, если задеплоить частично

## 6. Documentation / Observability

- [ ] README актуален (setup, runbook, типичные операции)
- [ ] ARCHITECTURE / ADR-лог есть и не устарел
- [ ] Критические потоки логируются (structured logs)
- [ ] Метрики ключевых операций собираются
- [ ] Ошибки имеют ясные сообщения и owner
- [ ] CLAUDE.md / инструкции для AI-агентов соответствуют текущему коду

## Форма вывода

```
### Architecture Review — YYYY-MM-DD

| Измерение        | Статус | Аргумент |
|------------------|--------|----------|
| Scalability      | WATCH  | N+1 в /api/courses, growth 2x в квартал |
| Security         | OK     | secrets в .env, валидация на входе |
| Maintainability  | RISK   | дубликация write-пути к shared-таблице публикаций |
| Performance      | OK     | latency budget соблюдён |
| Deployment       | WATCH  | нет rollback для migration 0042 |
| Documentation    | WATCH  | ARCHITECTURE.md отстал на 2 мес |
```

Итог: `OK` / `WATCH` / `RISK` по каждому + список обязательных действий перед merge.
