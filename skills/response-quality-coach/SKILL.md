## Роль
Коуч качества ответов: разбираю плохой ответ на дефекты, нахожу корень, предлагаю минимальную правку инструкции и фиксирую случай в реестре для последующей обработки.

## Когда использовать
- Ответ в чате слабый, неясный, неверный или слишком многословный
- Skill выдал артефакт, не соответствующий output contract
- Нужно откалибровать skill по реальному примеру сбоя
- Пользователь явно недоволен и просит разобрать почему

## Порядок работы

### Шаг 0: Определение источника
1. По умолчанию источник — текущий чат, если явно не указан другой пример
2. Зафиксировать: исходный prompt, плохой response, ожидаемое поведение
3. Прочитать известные дефекты:
   - `~/projects/IDE_booster/Docs/ai/ANSWER_ERRORS.md` — мастер-реестр (17 классов дефектов)
   - `~/.claude/skills/claude-booster/references/skills-errors.md` — реестр skill-уровня
4. (Опционально) `references/content-analyzer-findings.md`, если существует — курируемые внешние находки по качеству ответов (knowledge-pipeline, внутренней задаче/293)
5. Если случай совпадает с известным паттерном — сослаться на него в анализе

### Шаг 1: Классификация дефектов
Применить [references/defect-taxonomy.md](references/defect-taxonomy.md) и реестры выше.

Известные классы: FACT, LOGIC, ASSUMPTION, MISSED_INTENT, SCOPE_DRIFT, FORMAT_MISMATCH, CLARITY, NOISE, TONE, ACTIONABILITY, UNVERIFIED, POLICY, RISK_OMISSION, UI_BLOAT, NAV_AMBIGUITY, INSTRUCTION_GAP, CONTEXT_GAP, EXECUTION_GAP + проектные.

### Шаг 2: 5 Whys
Свести сбой к одной из трёх корневых причин:
- **instruction gap** — skill не содержит нужной инструкции
- **context gap** — skill не подтянул нужный контекст (файл/реестр/история)
- **execution gap** — инструкции правильные, модель не исполнила

Протокол: [`~/.claude/skills/claude-booster/references/rca-protocol.md`](../claude-booster/references/rca-protocol.md).

### Шаг 3: Корректный ответ
Сформулировать исправленный ответ с только необходимыми правками — не переписывать всё.

### Шаг 4: Durable fix
Применить [references/durable-fix-patterns.md](references/durable-fix-patterns.md) — сформировать конкретную правку skill'а или инструкции.

### Шаг 5: Логирование в реестр
Выбрать правильный реестр:
- **Response-уровень** (плохой текст, неверный формат, слабая формулировка) → `~/projects/IDE_booster/Docs/ai/ANSWER_ERRORS.md`
- **Skill-уровень** (skill выдал не тот артефакт, пропустил шаг, игнорировал контракт) → `~/.claude/skills/claude-booster/references/skills-errors.md` со статусом OPEN, формат из самого файла
- **Смешанный случай** — запись в обоих реестрах со ссылками друг на друга

### Шаг 6: Патч виновника
- Claude skill-дефект → передать в `/claude-booster` Режим D для RCA-обработки (или применить правку напрямую если простая)
- Cursor-виновник → через `/cursor-booster`
- Codex-виновник → через `/codex-booster`

### Шаг 7: Anti-bloat refactor pass
Перед финальным фиксом:
1. Свернуть повторяющиеся defect-specific инструкции в меньший инвариант
2. Предпочесть обновление checklist/reference над расширением верхнеуровневых инструкций skill
3. Удалить формулировки, дублирующие существующий guidance без улучшения покрытия

### Шаг 8: Чеклист верификации
Короткий checklist для проверки что фикс действительно устраняет класс дефекта, не вызывает регрессий.

## Контракт входа
- `Source Case` — источник (чат / конкретный прогон)
- `Task Prompt` — исходный запрос
- `Observed Response` — что выдала модель
- `Expected Behavior` — что ожидалось
- `Context Constraints` — опциональные ограничения

## Контракт результата
- `Defect Classes` — классы дефектов из таксономии
- `Severity` — S1/S2/S3
- `5 Whys` — цепочка до корня
- `Root Cause` — instruction / context / execution gap
- `Corrected Response` — исправленный ответ
- `Durable Instruction Fix` — конкретная правка skill/инструкции
- `Register Update` — запись в ANSWER_ERRORS.md и/или skills-errors.md
- `Target Artifact to Improve` — какой skill/правило править
- `Anti-bloat Report` — что уплотнено вместо добавления
- `Verification Checklist` — как проверить что фикс работает

## Apply-to-Text режим (pre-publish check копирайт-skill)

Вызывается копирайт-skill (`/digital-copywriter`, `/travel-copywriter`, любой будущий) на Шаге верификации перед выдачей результата. Или явно оператором: `/response-quality-coach scan-text {путь-к-файлу}`.

**Цель:** механический внешний прогон готового текста по M1-M14 из `~/.claude/skills/claude-booster/references/ai-humanness.md`. Без переоткрытия таксономии — ссылаемся на shared reference как на источник истины.

**Когда:** копирайт-skill закончил Шаг 3 «Верификация» (внутренние чеклисты). До Шага «Выдача» — обязательный внешний прогон.

**Алгоритм (по каждому маркеру M1-M14):**

1. **M1 (деепричастные нагромождения):** Grep по `-ая|-яя|-ив|-ыв` в одном предложении ≥2 раз — флаг.
2. **M2 (глаголы-связки):** Grep по стоп-листу `служит|выступает в качестве|представляет собой|является|осуществляется|производится` — каждое попадание = нарушение.
3. **M3 (списки из 3):** найти все списки, посчитать пункты. Все по 3 = флаг (требуется разнообразие).
4. **M4 (synonym cycling):** сложно автоматизировать — выборочно проверить упоминания центрального объекта на 3+ разных названиях в смежных абзацах.
5. **M5 (overhedging):** Grep по `важно отметить|стоит отметить|следует отметить|стоит учитывать|стоит помнить|необходимо понимать|важно понимать|стоит подчеркнуть|по сути|в принципе|в целом|фактически|зачастую` — каждое = нарушение.
6. **M6 (пустые эпитеты):** Grep по `уникальн|потрясающ|невероятн|ведущ|качественн(ый\|ая\|ое)|эффективн|инновационн|передов|комплексн|оптимальн` — каждое = нарушение.
7. **M7 (канцелярит):** Grep по `данный|указанный|вышеупомянут|осуществить|произвести|в рамках|в плане|в части|с целью|посредством|играет ключевую роль|на сегодняшний день|в заключение` — каждое = нарушение.
8. **M8 (тире):** `grep -c "—"` по файлу. Считать тире / (слов / 1000). Лимит ≤3 на 1000 слов. Превышение в 2+ раза = критическое нарушение.
9. **M9a (не X, а Y):** Grep по паттерну `не [А-Яа-я]+, а [А-Яа-я]+|не [А-Яа-я]+, это [А-Яа-я]+`. Для длинных текстов лимит 1; для коротких (<800 знаков, DM/outreach) — 0.
10. **M9b (инста-обёртки) — ЖЁСТКИЙ ЗАПРЕТ:** Grep по полному стоп-листу из ai-humanness.md (M9b):
    - `это про |будет про |уже про |теперь про |не про .+, а про |тут не про |вся история про |пост про то, как |когда ты понимаешь, что|и вот тут до меня дошло|вселенная подкинула|мне зашло|залетело|большой инсайт|важный инсайт|случился инсайт|приходит понимание`
    - Каждое попадание = FAIL. Сканировать **весь текст**, не только финал/bold. Ноль допусков.
11. **M10 (длина предложений):** разбить на предложения, посчитать длины в словах. Доля ≤7 слов должна быть ≥30%.
12. **M11 (гиперсвязность):** Grep по `таким образом|следовательно|кроме того|более того|в дополнение к этому|итак` — 2+ за текст = флаг.
13. **M12 (дидактика):** Grep по `давайте рассмотрим|необходимо понимать|обратите внимание|как мы видим|как уже было сказано` — каждое = нарушение.
14. **M13 (жаргон-дамп) — для смешанной/обывательской аудитории:** для каждого абзаца посчитать аббревиатуры (`\b[A-Z]{2,}\b`) и непереведённые англицизмы из стоп-листа (`pipeline|feature|pattern|prompt|commit|merge|deploy|runtime|framework|agent`). 3+ в абзаце без аналогии в этом же или предыдущем абзаце = нарушение.
15. **M14 (инструкции по силам читателю):** найти блоки с глаголами `проверьте|оцените|диагностируйте|определите|убедитесь|посмотрите` — пометить как требующие ручной проверки на выполнимость целевой аудиторией.

**Выдача:**

```
PRE-PUBLISH CHECK: {имя файла}
Слов: {N}, тире: {T} ({T/N*1000:.1f} на 1000)

M1 деепричастия:     PASS | FAIL — строки: ...
M2 связки:           PASS | FAIL — цитата + строка
M3 списки-3:         PASS | FAIL
M4 synonym cycling:  PASS | FAIL (manual)
M5 overhedging:      PASS | FAIL — цитата + строка
M6 пустые эпитеты:   PASS | FAIL — цитата + строка
M7 канцелярит:       PASS | FAIL — цитата + строка
M8 тире:             PASS | FAIL — фактическое значение / лимит
M9a не X, а Y:       PASS | FAIL — {N} вхождений, лимит {L}
M9b инста-обёртки:   PASS | FAIL — список цитат + строки (жёсткий запрет)
M10 ритм:            PASS | FAIL — доля коротких ≤7 слов: {D}%
M11 гиперсвязность:  PASS | FAIL
M12 дидактика:       PASS | FAIL
M13 жаргон-дамп:     PASS | FAIL — абзацы с превышением
M14 инструкции:      MANUAL — блоки требующие ревью эксперт→обыватель

ВЕРДИКТ: PASS / FAIL ({K} критических нарушений)

Если FAIL — копирайт-skill ОБЯЗАН переписать соответствующие фрагменты перед выдачей. Не «исправить точечно», если 3+ маркеров FAIL.
```

**Реализация (без отдельного скрипта):** прогон выполняется в самом skill через серию Grep/Bash-вызовов по приведённым паттернам. Все нарушения собираются в один отчёт. Это минимально достаточная автоматизация — без новых зависимостей.

**Интеграция с копирайт-skills:**
- `/digital-copywriter` Шаг 3d → вызывает этот режим до Шага 4 (выдача)
- `/travel-copywriter` — добавить аналогично при следующем аудите
- Любой новый копирайт-skill — `Apply-to-Text` обязателен в шаблоне `content-skill-template.md`

**Если FAIL после двух итераций переписывания** — фиксировать инцидент в `skills-errors.md` (M-маркер как класс дефекта) и эскалировать.

## Apply-to-Skill режим
При калибровке конкретного skill:
1. Использовать одну реальную пару prompt/response (по умолчанию — текущий чат)
2. Сравнить output с таксономией и intended output contract skill'а
3. Предложить точные правки в `SKILL.md` (file:line)
4. Залогировать дефект в `skills-errors.md`
5. Правки минимальные, проверить на одном follow-up случае

## Правила качества
- **Конкретность и доказательность** — никакой общей критики
- **Не переписывать всё**, если один класс дефекта объясняет сбой
- **Компактные testable правки** вместо длинной прозы
- **Для планов/спек/ревью** — явно проверять целостность фазы, доменную полноту, минимально достаточную документацию
- **Калибровка неполна** если финальный фикс оставляет очевидный bloat инструкций или дубли guardrails
- **Dual-register awareness** — различать response-уровень и skill-уровень дефектов, логировать в правильное место

## Обратная связь
Проблема с этим skill → дефект самого `/response-quality-coach` фиксируется в `~/.claude/skills/claude-booster/references/skills-errors.md` вручную (оператором или другим AI-агентом), далее `/claude-booster` Режим D применяет RCA (5 Whys + anti-bloat check) перед фиксом.
