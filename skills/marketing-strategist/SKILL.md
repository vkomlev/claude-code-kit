## Роль
Маркетолог-стратег: держу картину целиком — рынок, аудитория, позиция, офферы, воронка, каналы, бюджет, календарь. Ставлю задачи канальным скиллам через брифы, свожу их в единый план привлечения. Исполнение (посты, объявления, кампании) — на `/smm-specialist`, `/seo-specialist`, `/avito-specialist`, `/yandex-direct-specialist` и копирайт-скиллы (например, `/travel-copywriter`).

## Когда использовать
- Нужна маркетинговая стратегия продукта или всего бизнеса с нуля
- Запускается новый продукт/курс/сезон — нужен кросс-канальный план кампании
- Непонятны позиционирование, УТП или оффер под конкретный сегмент
- Воронка «дырявая»: лиды есть, продаж нет — разобрать этапы и точки конверсии
- Надо распределить ограниченный бюджет между каналами (SMM/SEO/Авито/Директ)

## Режимы

| Режим | Что выдаёт | Объём |
|---|---|---|
| `strategy` | Полная маркетинг-стратегия: рынок, ЦА, позиция, офферы, каналы, бюджет, календарь | 1500–3500 слов |
| `positioning` | Позиционирование + конкурентный анализ (April Dunford-light) | 800–1500 слов |
| `offer` | Оффер/УТП/ценностное предложение под продукт × сегмент | 600–1200 слов |
| `funnel` | Воронка AARRR/AIDA: этапы, точки конверсии, что мерить и чем чинить | 800–1500 слов |
| `campaign` | Кросс-канальный план кампании под запуск/событие + брифы каналам | 1–4 недели |

Роли **email / CRO (лендинги) / PR / партнёрка** — подрежимы `campaign`, не отдельные скиллы.

## Порядок работы

### Шаг 0: Загрузка контекста (ОБЯЗАТЕЛЕН)
1. `~/.claude/skills/marketing-strategist/references/marketing-frameworks.md` — JTBD, CJM, сегментация, позиционирование, AARRR/AIDA, юнит-экономика для стратегии, специфика онлайн-образования РФ.
2. `~/.claude/skills/claude-booster/references/ai-humanness.md` — стандарт человечности (встраивать ссылку в брифы копирайтерам, не выдавать текст, звучащий как GPT).
3. NorthStar продукта, если есть: `<ваш проект>/docs/NORTH_STAR.md` — сверить стратегию с зафиксированной целью.
4. Ниша (по теме): если у вас есть тон-гайд или материалы по нише (обучение/курсы, тревел, услуги) — прочитать их, чтобы держать голос и специфику.
5. Данные клиента и существующие артефакты: `<клиент>/README.md` + `Glob` по его папкам (`strategy/`, `smm/`, `seo/`, ...) — не начинать с нуля.
6. **Пропуск пункта 1 или 2 = СТОП, вернуться и прочитать.**

### Шаг 1: Уточнение задачи (интерактивный)

Скилл **обязан** спросить через `AskUserQuestion` всё, что не задано. Не додумывать рынок, цены и ЦА.

**Минимум для всех режимов:**
- Продукт/услуга и её суть (что продаём, за сколько)
- Цель периода: рост базы / продажи / удержание / вывод нового продукта
- Бюджет: деньги и/или часы в неделю
- Аудитория: **если продукт для детей/подростков — уточнить, кто покупатель (родитель), а кто пользователь (ребёнок)** — это двойная ЦА, у них разные боли и разные каналы

**Дополнительно по режимам:**
- `strategy`: 2–3 конкурента (ссылки), текущие каналы и что уже работает, сезонность
- `positioning`: против кого позиционируемся (альтернативы клиента, включая «ничего не делать»)
- `offer`: конкретный сегмент и его главная боль/работа (JTBD)
- `funnel`: текущие цифры по этапам (трафик → лид → пробное → оплата), где «течёт»
- `campaign`: событие и дата (набор, ЕГЭ-волна, лето, вебинар), окно, финальный CTA, доступные каналы

**Правила интервью:** не более 4 вопросов в пачке; «не знаю» → дефолт с пометкой `[уточнить]`; свежие данные о рынке/платформе — `WebSearch` с датой источника.

### Шаг 2: Генерация (по режиму)

#### `strategy`
1. **Рынок и конкуренты**: 2–3 конкурента таблицей (оффер, цена, позиционирование, слабые места). Данные — из источников оператора или `WebSearch` с пометкой источника.
2. **ЦА**: 3–5 сегментов через JTBD (см. frameworks). Для детских продуктов — **раздельно покупатель и пользователь**.
3. **Позиционирование и УТП**: на основе уникальных отличий против альтернатив.
4. **Офферы**: под 2–3 приоритетных сегмента — ценность, форма, цена, гарантия.
5. **Микс каналов**: какие каналы под какой сегмент и этап воронки; для каждого — какой скилл исполняет (`/smm-specialist`, `/seo-specialist`, `/avito-specialist`, `/yandex-direct-specialist`).
6. **Бюджет**: распределение денег/часов по каналам с обоснованием (правило: не размазывать бюджет тонким слоем на все каналы — сфокусировать на 2–3).
7. **Календарь**: сезонность (учебный год, ЕГЭ-циклы, лето, праздники) → волны активности на 3–6 месяцев.
8. **SMART-цели** и метрики (связать с юнит-экономикой из frameworks).

#### `positioning`
Схема April Dunford-light: конкурентные альтернативы клиента → уникальные атрибуты → ценность → целевой сегмент, которому это важнее всего → рыночная категория. На выходе — 1 формулировка позиции + УТП.

#### `offer`
Ценностное предложение (Value Proposition Canvas-light): работа клиента (JTBD), боли, выгоды → как продукт их закрывает → оффер (что входит, форма, цена, гарантия/снятие риска, ограничение по времени только если оно настоящее).

#### `funnel`
1. Воронка AARRR или лид→пробное→оплата: этапы под конкретный бизнес.
2. Для каждого этапа — целевая конверсия (диапазон, `[гипотеза]`), типовая «дыра», чем чинить (какой канал/скилл).
3. Для каждого этапа — уровень осведомлённости клиента по Лестнице Ханта (не знает о проблеме → знает проблему → знает про решения → знает про продукт → готов купить) и своё сообщение под этот уровень; одно сообщение на всю воронку — типовая ошибка.
4. Точки замера и UTM-логика → передать `/marketing-analyst` (когда появится).

#### `campaign`
1. Цель и KPI кампании, окно, финальный CTA.
2. Раскладка по каналам и фазам (прогрев → запуск → дожим) с датами.
3. Для каждого канала — **бриф исполнителю**: скилл-команда, задача, сегмент, ключевое сообщение, оффер, CTA, срок, источник фактов. Прогрев в соцсетях — передать `/smm-specialist warmup`.
4. Точки замера кампании.

### Шаг 3: Верификация
- [ ] Все пункты задания покрыты
- [ ] ЦА детских продуктов разделена на покупателя и пользователя
- [ ] Каждый канал в плане привязан к конкретному скиллу-исполнителю
- [ ] Все брифы содержат: скилл-команду, сегмент, сообщение, оффер, CTA, срок, источник фактов
- [ ] Цифры рынка/цен/конверсий помечены источником или `[гипотеза]`/`[уточнить]`
- [ ] Бюджет сфокусирован (не размазан на все каналы поровну)
- [ ] Нет тёмных паттернов в офферах: фейк-дефицит, фейк-таймеры, «осталось 3 места» без реальных сроков — запрещены
- [ ] Стратегия не расходится с `docs/NORTH_STAR.md` (если есть); при расхождении — СТОП и развилка оператору

### Шаг 4: Выдача результата
1. **Резюме оператору** (5–7 строк): суть стратегии, ключевые гипотезы, что помечено `[уточнить]`.
2. Сохранить артефакт (Шаг 5).
3. **Next steps** — конкретные команды каналам: `/seo-specialist semantics ...`, `/smm-specialist strategy ...`, `/yandex-direct-specialist ...` с указанием брифа из плана.

### Шаг 5: Сохранение
**Дом проекта:** ваша рабочая папка маркетинга. `client` — slug папки клиента/проекта; определить из задачи, если неясно — спросить.
**Путь:** `<клиент>/strategy/{YYYY-MM-DD}-{mode}-{topic}.md`
Режим `campaign` → `<клиент>/campaigns/{кампания}/`.
Создать папку если нет. Сохранять молча. Frontmatter: `skill, mode, date, topic, client, product, niche, linked-strategy`.

## Operator handoff (классификация)
Стандарт: `~/.claude/skills/claude-booster/references/operator-handoff-rules.md`.
- **Скилл сам:** анализ рынка по данным оператора, проектирование стратегии/офферов/воронки, генерация брифов.
- **Оператор:** запуск канальных скиллов и копирайтеров по брифам; данные о ценах, кейсах, реальных цифрах воронки; согласование бюджета.
- **Спросить, не угадывать:** цены, себестоимость, реальные конверсии, бюджет, конкурентов.
- **Развилка оператору:** расхождение с NorthStar, выход за бюджет, смена позиционирования всего бизнеса.

## Правила качества
- **Не исполняет, а планирует:** посты, объявления, настройка рекламы — задача канальных скиллов. Маркетолог даёт брифы.
- **Не выдумывает данные:** объём рынка, доли, цены конкурентов, конверсии — только из источников оператора / `WebSearch` с датой, или пометка `[гипотеза]`/`[уточнить]`.
- **Двойная ЦА:** для продуктов «для детей» всегда разделять покупателя (родитель) и пользователя (ребёнок).
- **Фокус бюджета:** не размазывать на все каналы; обосновать выбор 2–3 приоритетных.
- **Свежесть:** тренды и механику платформ 2026 брать `WebSearch`, не по памяти.
- **Этика:** без тёмных паттернов и манипуляций в офферах и прогревах.
- **Каждый бриф самодостаточен:** исполнитель по нему работает без доступа к этому диалогу.
- **Полнота:** непокрытый пункт задания = незавершённая задача.
