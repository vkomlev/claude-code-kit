# Эвристики полноты по типу фичи

Используется на Шаге 4 `/feature-completeness-review`, когда нет спеки и нет
внутрипродуктового прецедента на соседнем экране. Это последний по приоритету
источник эталона — общий ориентир «что обычно ожидается», а не жёсткое правило:
при сомнении, применима ли эвристика к конкретному продукту, — `AskUserQuestion`
оператору, не штамповать находку.

## Источники (лучшие практики)

- **Gap Analysis** — бизнес-аналитическая техника «текущее состояние vs желаемое
  состояние»: применяется здесь на уровне «что показано» vs «что ожидается».
- **Definition of Done** (Scrum/agile-практика) — фича считается завершённой, когда
  закрыты не только happy path, но и edge cases (пусто/ошибка/загрузка), обратная
  связь на действия, права доступа по роли.
- Nielsen Norman Group, эвристика usability **№1 «Visibility of System Status»** —
  показанный статус/счётчик, который никуда не ведёт по клику, нарушает эту
  эвристику: система показала состояние, но не даёт с ним ничего сделать.
- Nielsen Norman Group, эвристика usability **№3 «User Control and Freedom»** —
  для действия, у которого обычно есть обратный путь (отменить, вернуть, дать ещё
  попытку), отсутствие такого пути — пробел, а не дизайн-решение по умолчанию.

## Таблица типовых ожиданий по типу фичи

| Тип фичи | Обычно ожидаемые действия | Частый недосмотр |
|---|---|---|
| **Список сущностей** (таблица, карточки) | фильтр, сортировка, поиск, пагинация/подгрузка, переход в деталь, массовое действие (если применимо к роли) | список есть, перехода в деталь или фильтра нет |
| **Карточка/деталь сущности** | все связанные подсущности видны И доступны для действия (комментарии, вложения, история изменений), действия редактирования/смены статуса согласно правам роли | подсущность отображается (иконка/счётчик), но не открывается и не имеет действия — «стеклянная витрина» |
| **Лента активности / уведомления** | переход к источнику события, отметить прочитанным/скрыть, кнопки действия, соответствующие типу события (не просто ссылка на «посмотреть») | клик открывает источник, но кнопки действия, ожидаемые для этого типа события, отсутствуют (пример внутренней задаче: открывается попытка ученика, но нет ни его комментария, ни кнопки «дать ещё попытку») |
| **Workflow проверки/модерации** (оценка работ, одобрение заявок) | просмотр присланного целиком, оставить комментарий/фидбек, принять/отклонить/вернуть на доработку, видна история предыдущих решений | можно посмотреть работу, но нельзя оставить комментарий или изменить решение — только просмотр |
| **Форма настроек/конфигурации** | сохранить, отменить с подтверждением несохранённых изменений, обратная связь по валидации, сброс к умолчанию (если применимо) | сохранение есть, но нет обратной связи об успехе/ошибке или подтверждения при уходе с несохранёнными правками |
| **Поиск / пустое состояние** | явный следующий шаг (что делать, если ничего не найдено/пока нет данных), а не голое «ничего не найдено» | пустое состояние есть, но не подсказывает, как перейти к непустому |

## Как использовать

1. Определить тип экрана/фичи по таблице (один экран может сочетать несколько типов — например, деталь + workflow проверки).
2. Сверить фактически доступные действия с колонкой «обычно ожидаемые».
3. Расхождение → потенциальный gap, severity по правилам Шага 5 основного SKILL.md.
4. Если тип фичи не укладывается ни в одну строку таблицы — не подгонять силой; вернуться к прецеденту (Шаг 4, приоритет 2) или явно спросить оператора, какой набор действий здесь ожидается.
