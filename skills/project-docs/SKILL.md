## Роль
Documentation-архитектор: создаю и поддерживаю два независимых слоя документации — для AI-агентов и для людей — так, чтобы каждый слой решал свою задачу без дублирования.

## Когда использовать
- Новый проект без документации → поднять AI- и human-слои с нуля
- Claude тратит много токенов на исследование кода при каждой задаче → нужна AI-карта проекта
- Документация устарела или разошлась с кодом
- Новый участник команды не может быстро понять как запустить/настроить проект
- Подготовка к передаче проекта или open-source релизу

## Режимы работы
- **full** — полная генерация с нуля (документация отсутствует или пользователь хочет переделать)
- **update** — инкрементальное обновление: читает существующие артефакты, добавляет недостающее, актуализирует устаревшее

Автовыбор: если в корне нет `CLAUDE.md` и `README.md` → full, иначе → update.
Явный: `/project-docs full` или `/project-docs update`.

## Порядок работы

### Шаг 0: Якорь контекста
Прочитать `~/.claude/projects/<project-slug>/memory/MEMORY.md` если существует — оттуда взять известные факты о проекте. Не выдумывать проекты, которых нет в памяти.

### Шаг 1: Discovery — сканирование проекта
Выполнить чеклист из `references/discovery.md`. Собрать:
- Стек (package.json, pyproject.toml, go.mod, Cargo.toml, requirements.txt)
- Топ-уровневую структуру (Glob `*`)
- Entry points (main.py, index.ts, app.py, cmd/)
- Конфиги (.env.example, config/, settings.py)
- Миграции/БД (alembic/, migrations/, schema.sql)
- Существующую документацию (README*, docs/, CLAUDE*, AGENTS*)
- Команды (scripts в package.json, Makefile, pyproject scripts)
- `git log --oneline -20` — контекст недавних изменений

Результат: карта проекта в рабочей памяти skill.

### Шаг 2: Уточнение аудитории и границ
Через AskUserQuestion (если не задано в команде):
- Тип проекта (web app / CLI / library / API / bot / data pipeline)
- Human-аудитория (внутренний dev / внешний dev / end-user)
- Режимы запуска (dev / prod / docker / test)
- Опциональные разделы (Architecture, Database, Security, Deployment)

### Шаг 3: План документации
Представить пользователю структуру артефактов и согласовать:

**Якорь цели:**
- `docs/NORTH_STAR.md` — конечная цель проекта (см. правило NorthStar в `~/.claude/CLAUDE.md`)

**AI-слой:**
- `CLAUDE.md` — ≤200 строк, якорь для Claude
- `docs/ai/architecture.md` — компоненты и потоки данных
- `docs/ai/data-model.md` — схемы БД, контракты API (если применимо)
- `docs/ai/workflows.md` — типовые флоу разработчика
- `docs/ai/errors.md` — known issues, антипаттерны
- `docs/ai/glossary.md` — доменные термины
- `AGENTS.md` — симлинк на CLAUDE.md (на Windows — копия с note о ручной синхронизации)

**Human-слой:**
- `README.md` — что делает проект, быстрый старт
- `docs/install.md` — требования, установка
- `docs/usage.md` — команды, режимы запуска
- `docs/configuration.md` — env vars, настройки
- `docs/troubleshooting.md` — типовые проблемы

### Шаг 4: Генерация артефактов

**Режим full:**
Использовать шаблоны из `references/templates-ai.md` и `references/templates-human.md`.
Создать файлы через Write.

**NorthStar (`docs/NORTH_STAR.md`) — первым:** зафиксировать конечную цель проекта — зачем он существует, какой результат считается успехом, ключевые ограничения. Если цель не выводится однозначно из кода/истории/памяти или неоднозначна — спросить оператора через AskUserQuestion **до записи**, не додумывать. В режиме update — сверить существующий файл и обновить только при явном расхождении.
Для AGENTS.md:
```bash
cd <project-root>
ln -sf CLAUDE.md AGENTS.md  # Unix
# Windows: копия файла + note вверху "Синхронизировать вручную с CLAUDE.md"
```

**Режим update:**
Прочитать существующие файлы. Определить расхождения (устаревшие пути, команды, стек).
По каждому файлу — минимальный патч через Edit. Если файла нет — создать по шаблону.

### Шаг 5: Наполнение CLAUDE.md
Принцип: "Удалил бы эту строку — Claude начал бы ошибаться?" Если нет — не писать.

Обязательные разделы (см. `references/templates-ai.md`):
1. **Project Overview** (2-3 строки): что делает проект, главная ценность
2. **Tech Stack**: язык, фреймворки, ключевые зависимости (одной строкой)
3. **Architecture** (краткая): главные компоненты + указатель на `docs/ai/architecture.md`
4. **Directory Structure**: дерево топ-уровня с 1-строчными комментариями
5. **Key Commands**: то, что нужно в ежедневной работе
6. **Coding Conventions**: только неочевидное (стиль — в линтерах)
7. **Workflows**: "перед правкой X — проверить Y"
8. **References**: ссылки на `docs/ai/*` с 1-строчным описанием

Лимит: ≤200 строк. Всё сверх — выносить в `docs/ai/`.

### Шаг 6: Наполнение README.md
1. **Hero**: название + 1-строчное описание
2. **Что делает проект** (2-3 абзаца для человека)
3. **Быстрый старт**: минимальные шаги до запуска
4. **Режимы запуска**: dev, prod, test, docker
5. **Документация**: ссылки на `docs/install.md`, `docs/usage.md`, `docs/configuration.md`
6. **Лицензия / Контакты** (если применимо)

Лимит: ≤150 строк.

### Шаг 7: Верификация
Пройти `references/quality-checklist.md`. Ключевое:
- CLAUDE.md ≤200 строк, README.md ≤150 строк
- Все ссылки из CLAUDE.md на `docs/ai/*` резолвятся
- Все ссылки из README.md на `docs/*` резолвятся
- AGENTS.md существует
- Нет дублирования между CLAUDE.md и README.md
- Нет credentials и секретов
- UTF-8 без BOM, Markdown валиден

### Шаг 8: Отчёт
Вернуть пользователю:
- Созданные/изменённые файлы (пути)
- Размеры ключевых файлов (строки)
- Gaps — разделы, которые пользователь должен заполнить вручную
- Следующие шаги (коммит, ревью человеком, настройка CI для актуализации)

## Контракт результата
- `Режим` — full / update
- `Созданные файлы` — список путей
- `Изменённые файлы` — список путей
- `Размеры` — строки CLAUDE.md и README.md
- `Gaps` — что требует ручного заполнения
- `Следующие шаги` — действия пользователя после skill

## Правила качества
- **NorthStar**: при первичной обвязке создать `docs/NORTH_STAR.md` с конечной целью проекта; при неоднозначности цели — уточнить у оператора до записи, не сочинять (см. правило NorthStar в `~/.claude/CLAUDE.md`)
- **Принцип удаления**: каждая строка в CLAUDE.md должна отвечать "Удалил — Claude ошибётся?". Если нет — вырезать
- **Progressive disclosure**: детали в `docs/ai/`, в CLAUDE.md только pointer + 1 строка описания
- **AI vs human**: CLAUDE.md и `docs/ai/` — сухие факты для ориентации AI. README.md и `docs/` — нарратив и примеры для человека
- **Не дублировать**: факты про стек/команды живут в CLAUDE.md, human-нарратив — в README.md
- **Не писать очевидное**: style guidelines, git basics, "используйте типы" — это линтеры и глобальный CLAUDE.md
- **Не hardcode credentials**: только имена env-переменных, никогда значения
- **Размер**: CLAUDE.md ≤200 строк, README.md ≤150 строк
- **AGENTS.md на Windows**: симлинк или копия с note "Синхронизировать вручную с CLAUDE.md"
- **Режим update**: только Edit с минимальным diff. Никогда Write поверх существующего файла без явного согласия пользователя
- **Encoding**: UTF-8 без BOM для всех артефактов
- **Никогда не выдумывать**: если факт не найден в коде/конфигах/истории — оставить gap в отчёте, не сочинять
