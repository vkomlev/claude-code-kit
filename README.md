# Claude Code Kit — стартовый комплект скиллов и правил

Готовая рабочая среда для [Claude Code](https://claude.com/claude-code): набор
переносимых скиллов (планирование, исполнение, ревью, QA, маркетинг), шаблон общих
правил и хук-«гейт», который заставляет агента выбирать профильный скилл до работы.

Комплект собран из реальной боевой среды и **обезличен**: все личные пути, боевые
хосты, доступы к БД, имена проектов и клиентов убраны. Ты подключаешь его к своим
проектам и дописываешь под себя.

---

## Что внутри

```
claude-code-kit/
├── README.md              ← этот файл: установка и использование
├── CLAUDE.md.example      ← шаблон общих правил (роль агента, цикл, стандарты, handoff)
├── settings.json.example  ← пример настроек: подключение хуков + защита от опасных команд
├── skills/                ← 40 скиллов (папка = один скилл)
├── hooks/                 ← гейт «профильный скилл до правки кода» + проактивная подсказка
│   ├── skill_engage_gate.py    — блокирует правку исходника мимо скилла
│   ├── skill_routing_hint.py   — подсказывает профильный скилл до работы (опционально)
│   ├── skill_routing.py        — общая библиотека (нужна обоим хукам)
│   ├── skill_routing.json      — реестр «проект → профильные скиллы» (настраивается)
│   └── README.md               — как работает гейт и как его настроить
└── docs/
    ├── skills-overview.md ← каталог всех скиллов с кратким описанием
    └── customize.md       ← как адаптировать комплект под свои проекты
```

## Что нужно заранее

1. **Claude Code** установлен и работает (`claude` в терминале или расширение в VS Code).
2. **Python 3** в PATH — только если хочешь использовать хуки (`python --version`).
   Без Python скиллы и общие правила работают, а хуки — нет.

## Установка

Всё живёт в домашнем каталоге Claude Code: `~/.claude/` (Windows:
`C:\Users\ИМЯ\.claude\`, macOS/Linux: `/Users/имя/.claude/` или `/home/имя/.claude/`).

### Шаг 1. Скиллы

Скопируй папки из `skills/` в `~/.claude/skills/`.

**Windows (PowerShell):**
```powershell
Copy-Item -Recurse -Force .\skills\* "$env:USERPROFILE\.claude\skills\"
```
**macOS / Linux:**
```bash
mkdir -p ~/.claude/skills && cp -r ./skills/* ~/.claude/skills/
```
Проверка: запусти `claude`, набери `/` — в списке появятся `/spec-writer`, `/executor-lite`
и остальные.

### Шаг 2. Общие правила

Если у тебя ещё НЕТ своего `~/.claude/CLAUDE.md` — скопируй шаблон и переименуй:
```bash
cp ./CLAUDE.md.example ~/.claude/CLAUDE.md
```
Если файл уже есть — не затирай его, а перенеси нужные разделы вручную. Дальше **отредактируй
под себя**: язык общения, стек, стандарты коммитов (см. `docs/customize.md`).

### Шаг 3. Хуки (опционально, но рекомендуется)

Хук `skill_engage_gate.py` не даёт агенту править код мимо профильного скилла — главная
причина, по которой скиллы реально начинают использоваться, а не простаивают.

1. Скопируй файлы:
   ```bash
   cp ./hooks/*.py ~/.claude/hooks/
   cp ./hooks/skill_routing.json ~/.claude/hooks/
   ```
2. Открой `hooks/skill_routing.json` в `~/.claude/hooks/` и **впиши свои проекты**: в блоке
   `rules` замени два примера на свои (путь `root`, каталоги с кодом, профильные скиллы).
   Подробно — в `hooks/README.md`.
3. Подключи хуки в `~/.claude/settings.json` — возьми блок `hooks` из `settings.json.example`
   и **замени `ИМЯ_ПОЛЬЗОВАТЕЛЯ` в путях на свой домашний каталог**. На macOS/Linux используй
   `python3` и путь вида `~/.claude/hooks/skill_engage_gate.py`.

Хуки перечитываются на лету — перезапуск Claude Code не нужен. Если Python не установлен —
пропусти этот шаг, остальное работает.

## Как этим пользоваться

- **Явный вызов:** набери `/имя-скилла` (например `/spec-writer`) — скилл берёт задачу в
  работу по своему протоколу.
- **Автоподбор:** по правилу из `CLAUDE.md` агент сам подбирает подходящий скилл, если ты
  его не назвал, и сообщает выбор одной строкой.
- **Типичный цикл:** размытая задача → `/spec-writer` (план + критерии) → `/executor-lite`
  или `/executor-pro` (реализация) → `/review-gate` (независимое ПРИНЯТО/ОТКЛОНЕНО) → слияние.
- **Улучшение среды:** `/claude-booster` — «инженер инфраструктуры»: аудит и правка самих
  скиллов, настроек, хуков, `CLAUDE.md`. Им же добавляют новые скиллы.

Полный каталог скиллов с описанием — `docs/skills-overview.md`.

## Настройка под себя

Комплект — это основа, а не готовая под тебя конфигурация. Минимум, что стоит сделать:
- отредактировать `~/.claude/CLAUDE.md` (стек, стандарты, что переводить/не переводить);
- вписать свои проекты в `~/.claude/hooks/skill_routing.json`;
- удалить скиллы, которые тебе не нужны (просто убери их папки из `~/.claude/skills/`).

Пошагово — в `docs/customize.md`.

## Обновление

Комплект — git-репозиторий. Чтобы получить свежую версию:
```bash
git pull
```
затем повтори копирование нужных частей (Шаг 1–3). Свой `CLAUDE.md` и `skill_routing.json`
не перезаписывай слепо — переноси изменения вручную, чтобы не потерять свои правки.

## Что намеренно убрано

Комплект собран из личной среды и очищен. В нём НЕТ и не должно быть: боевых хостов и
доступов к БД, личных путей и имён проектов, кросс-проектного трекера задач, кросс-агентной
координации, скиллов под чужой бизнес (публикация курсов, личный голос копирайтера) и
инструментов, выведенных из стека. Если найдёшь где-то оставшийся личный след — это ошибка
сборки, сообщи автору курса.
